# Migrations

Alembic database migrations for PymtHouse.

## Usage

```bash
make migrate                       # apply all unapplied migrations
make migrate-create m="add foo"    # autogenerate a new revision from model changes
uv run alembic downgrade -1        # roll back one revision
uv run alembic current             # show current head
uv run alembic history             # list all revisions
```

## File naming

Files are named `NNNN_<slug>.py` (e.g. `0001_initial_schema.py`). Sequential
numbering makes them easy to grep and read in order.

## Conventions

- Don't edit a migration after it's been applied anywhere. Write a new one.
- Don't mix model changes from different domains in one migration unless they
  depend on each other (e.g. adding a table and an FK that references it).
- Hand-edit autogenerated migrations to remove false-positives (column-type
  ordering changes, etc.) before committing.
- Wei amounts: `sa.Numeric(78, 0)`.
- UUIDs: `sa.Uuid()` (portable across dialects).
- Timestamps: `sa.DateTime(timezone=True)` with `server_default=sa.func.now()`.
